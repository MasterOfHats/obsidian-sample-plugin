## Project Overview

This is an Obsidian plugin built with TypeScript and bundled with esbuild into a single `main.js` file. The plugin extends Obsidian's `Plugin` base class and demonstrates ribbon icons, status bar items, commands, modals, settings, and event listeners.

## Build Commands

- `npm run dev` — Watch mode: compiles and rebuilds on file changes
- `npm run build` — Production build: type-checks with tsc, then bundles/minifies with esbuild
- `npm run lint` — Run ESLint (uses flat config with obsidian-specific rules)
- `npm run version` — Bump version in manifest.json and versions.json

There are no test commands configured.

## Architecture

- **Entry point:** `src/main.ts` — Exports default `MyPlugin` class extending `Plugin`. Handles lifecycle (`onload`/`onunload`), commands, ribbon icons, and settings loading.
- **Settings:** `src/settings.ts` — Defines `MyPluginSettings` interface, `DEFAULT_SETTINGS`, and `SampleSettingTab` (extends `PluginSettingTab`). Settings persist via `loadData()`/`saveData()`.
- **Build output:** `main.js` — Single CommonJS bundle generated by esbuild. Externals: `obsidian`, `@codemirror/*`, `@lezer/*`, and Node builtins are not bundled.
- **Manifest:** `manifest.json` — Plugin ID (`sample-plugin`), version, and `minAppVersion` must stay in sync with `versions.json`.

## Key Conventions

- Source code lives in `src/`. Keep `main.ts` minimal (lifecycle only); split features into separate modules.
- Suggested structure for growth: `src/commands/`, `src/ui/`, `src/utils/`, `src/types.ts`.
- TypeScript strict mode is enabled (`noImplicitAny`, `strictNullChecks`, `noUncheckedIndexedAccess`).
- Base URL is `src/` so imports resolve relative to that directory.
- Indentation: tabs (4-space width), LF line endings.

## Release Process

1. Bump version in `manifest.json` (SemVer, no `v` prefix)
2. Update `versions.json` with version → minAppVersion mapping (or use `npm run version`)
3. Create GitHub release tag matching the version number
4. Attach `manifest.json`, `main.js`, and `styles.css` as release assets

## Important Notes

- `main.js` is gitignored — it's a build artifact, not source code
- `data.json` is gitignored — it contains user settings created by Obsidian at runtime
- Never change the plugin `id` in manifest.json after release
- Default to local/offline operation; no hidden telemetry; never execute remote code
- Keep startup light; defer heavy work; debounce expensive operations
- Test on mobile when `isDesktopOnly` is false (currently false)
